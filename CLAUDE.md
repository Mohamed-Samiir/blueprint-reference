# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`blueprint-reference` is a **reference application**, not a product. Work is built and
verified here, then a separate repo — `blueprint-platform` (the "foundation preset"
generator) — copies the verified pieces into its emitted templates. This repo never
imports or modifies `blueprint-platform`.

- `SYNC_LOG.md` tracks what has moved to `blueprint-platform`. Entries tagged
  `sync/<feature>/<version>` are real syncs; untagged **PREPARATION** entries record
  work verified here but not yet synced.
- `TASKS/*.md` are task lists. They assume everything in this file without repeating it,
  and are explicit about what is in scope for `blueprint-reference` vs. deferred to a
  later generator-side task list.
- `src/app/config/manifest.types.ts` has **no runtime role** here — it documents the
  data shape the generator will write to `.blueprint/manifest.json` in generated
  projects.

When a task says "sync-ready check", it means: no hardcoded colors (spartan token
names only), compiles under `ng build` (prod/AOT) and development, brain/behavior
layer untouched from generator output (`git diff` clean), verified in the preview UI.

## Commands

```bash
npm start                       # ng serve — dev server at http://localhost:4200
npm run build                   # ng build — production build to dist/
npm run watch                   # ng build --watch --configuration development
npm test                        # ng test — Vitest via @angular/build:unit-test builder
npx ng test --include src/app/app.spec.ts   # run a single spec file
npx prettier --write .          # format (no ESLint is configured in this repo)
```

- Generate an app component: `ng generate component name` (scss styles, `app` selector prefix).
- Generate a spartan UI primitive: `ng g @spartan-ng/cli:ui --name=<x>` (style `nova`,
  output under `src/app/ui/<x>/src/`). After generating, add its `@blueprint-platform/ui/<x>`
  path to `tsconfig.json` and wire any new color tokens (see Theming).
- Tests use `vitest/globals` + `jsdom`. `src/app/app.spec.ts` is stale generator boilerplate
  (asserts an `<h1>` that `app.html` no longer renders) — don't treat its failure as a regression.

## Architecture

**Angular 22, zoneless, fully standalone.** No NgModules. `provideZonelessChangeDetection()`
in `app.config.ts`; components use `ChangeDetectionStrategy.OnPush`, signals, and the
`inject()` function. TypeScript is strict-plus (`noPropertyAccessFromIndexSignature`,
`noImplicitReturns`, `noImplicitOverride`).

### UI layer — `src/app/ui/**` (spartan-ng "helm")

~60 component folders (`accordion`, `button`, `dialog`, `sidebar`, …), each with its own
`src/index.ts` barrel and `src/lib/hlm-*.ts` files. These are **vendored, own-your-code
copies** generated by the spartan CLI, not an installed package. They are consumed through
`tsconfig.json` path aliases like `@blueprint-platform/ui/button` → `./src/app/ui/button/src/index.ts`.
Each barrel exports an `Hlm<Name>Imports` array for `imports: [...]`.

- `src/app/ui/utils/src/lib/hlm.ts` — `hlm()` (clsx + tailwind-merge) and `classes()`, a
  MutationObserver-based dynamic class manager used by every helm component.
- `src/app/ui/utils/src/lib/provide-spartan-hlm.ts` — `provideSpartanHlm()` sets CDK
  overlay `usePopover: false` so overlays render above `position: fixed` elements.
- Treat generated helm files as untouched baseline. Compose them in app code; don't edit
  the primitives (a `git diff` on them must stay empty for sync).

### Theming — hand-rolled, three layers

This repo does **not** import `@spartan-ng/brain/hlm-tailwind-preset.css`. Instead:

1. **SCSS token maps** — `src/styles/tokens/_palette-default.scss` and
   `_palette-brand-x.scss` (Sass maps of semantic name → hex), plus `_scale.scss` (spacing).
2. **Emit** — `src/styles/tokens/theme.scss` runs the `emit-vars` mixin (`_emit.scss`) to
   write each map to CSS custom properties: `--<name>` on `:root` for the default palette,
   and again scoped to `.theme-brand-x` for the alternate palette.
3. **Tailwind v4 bridge** — `src/styles/tailwind-theme.css` `@theme inline` block maps
   `--color-<x>: var(--<x>)` so utilities like `bg-sidebar`, `text-muted-foreground` resolve.

All three global stylesheets are registered in `angular.json` `styles[]` (`src/styles.scss`,
`src/styles/tokens/theme.scss`, `src/styles/tailwind-theme.css`).

**Adding a new color token requires editing three files**: both `_palette-*.scss` maps and
`tailwind-theme.css`. Palette switching at runtime = toggling the `.theme-brand-x` class on
a wrapper element. Never hardcode a color in app/layout code — use the semantic token
utilities only.

### Config layer — `src/app/config/`

`BLUEPRINT_CONFIG` injection token (`template-config.ts`) carries `{ palette, rtl,
labelPosition }`. `provideBlueprint(partial)` merges over `DEFAULT_BLUEPRINT_CONFIG` and is
spread into `app.config.ts` providers.

### Layout shells — `src/app/layout/**`

`sidebar-shell`, `floating-shell`, `inset-shell` — one thin standalone component per spartan
sidebar `variant`. **Deliberately independent copies, no shared base class**, matching the
copy-based philosophy (a generated project must be able to edit one without touching the
others). Each composes `hlm-sidebar-*` primitives + a `<router-outlet>`.

**RTL:** spartan's sidebar `side` input is a *physical* anchor and does **not** auto-flip
under `dir="rtl"`. Each shell injects `Directionality` (`@angular/cdk/bidi`) and computes
`side = dir === 'rtl' ? 'right' : 'left'` itself. The mobile off-canvas path (`<hlm-sheet>` via
CDK overlay, `<768px`) is shared across all three variants. See `src/app/layout/README.md`
for the full generator-output inspection notes.

### Preview — `src/app/layout-preview/**`

Permanent dev tool (not production quality, **never synced**). Lazy route `layout-preview`
(`app.routes.ts`) with children `sidebar` / `floating` / `inset`, each mounting a shell around
a shared placeholder page. The toolbar has a variant switcher, an RTL (`dir`) toggle, and a
palette (`.theme-brand-x`) toggle so every combination is reachable without code edits.

## Conventions

- Prettier: `printWidth: 100`, `singleQuote: true`; `.editorconfig` sets 2-space indent,
  final newline, single quotes in `.ts`.
- Templates: prefer inline `template:` for small shells (as the layout components do);
  `templateUrl` + `.html` for the root app.
- Use control-flow syntax (`@for`, `@if`) and `track`, not `*ngFor` / `*ngIf`.
